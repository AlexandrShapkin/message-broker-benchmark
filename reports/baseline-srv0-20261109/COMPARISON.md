# Контракт будущего сравнения

Первичный источник — версионированный архив Release `baseline-srv0-20261109-v1`,
не рисунки или старые checkpoint-таблицы сервера. Оригинальные файлы результатов
не редактируются. Реестр `run-register.csv` содержит каждую обнаруженную попытку,
включая неудачные и незавершённые. Подробности и исходные метаданные — `audit.json`.

`runs.csv/json/parquet` — прошедшие строгую проверку запуски финальной серии.
`validated-runs.*` дополнительно содержит проверенные вспомогательные запуски;
их нельзя автоматически смешивать с финальной серией.
`comparison.*` — агрегаты **строгих** групп `group_id`.
`observed-final-runs.*` — все проверенные финальные наблюдения, включая disk alarm;
`timeline.*` — временные ряды всех этих наблюдений, секунды от MEASURE.
Для основной cohort выбирать run_id из runs.csv; нельзя включать все timelines автоматически.
`run-register.*` — исчерпывающий статус и причина включения/исключения.

`valid` означает прохождение штатной artifact/resource-проверки. Пригодность
для основной cohort определяется `included` в реестре; `host_disk_pressure`
может исключать формально valid completed observation.

CSV: UTF-8, LF, десятичная точка; пустое поле означает null, не ноль.
JSON сохраняет типы; Parquet — удобная типизированная копия.

Основные единицы:

| Поля | Значение |
|---|---|
| `clients`, `producers`, `subscribers` | Логические объекты клиентов; не TCP-соединения |
| `active_producers`, `active_consumers` | Активная прикладная топология |
| `connections`, `connections_mean` | Максимум и среднее наблюдаемых broker-side established TCP endpoints в MEASURE; не сумма всех когда-либо открытых сокетов |
| `requested_rate` | Запрошенные сообщения / длительность MEASURE, сообщ./с |
| `offered_rate` | Попытки Publish (`sent`) / длительность MEASURE, сообщ./с |
| `accepted_rate` | Успешные операции клиентского API в MEASURE / длительность, сообщ./с; семантика ack зависит от драйвера |
| `delivered_rate` | Полученные копии в MEASURE / длительность, копий/с |
| `p50`, `p95`, `p99`, `p99_9`, `max` | Задержка от планового времени до доставки, мс; верхняя граница HDR bucket; включает доставленное в cooldown |
| `lost`, `duplicates`, `unexpected`, `reordered`, `errors` | Счётчики, копии или операции согласно методологии |
| `cpu_mean`, `generator_cpu_mean` | Проценты одного ядра, могут быть >100 |
| `rss_mean`, `rss_peak`, `generator_rss_mean` | Байты; RSS процесса, не вся память host |
| `network_rx`, `network_tx`, `disk_read`, `disk_write` | Разность накопительных счётчиков на доступном интервале выборок в MEASURE, байты |
| `fault_duration_seconds`, `throughput_recovery_seconds` | Секунды; null означает отсутствие применимого наблюдения, не ноль |

Для статистических полей суффиксы `mean`, `median`, `min`, `max`, `stddev`, `n`
относятся к распределению **по запускам**. `p99_mean` не является объединённым p99.
Совместные гистограммы в этой публикации не объединялись. В baseline CI не
экспортируются: малое n и последовательная серия недостаточны для устойчивых
inferential выводов. Штатный анализатор поддерживает bootstrap среднего,
но здесь используются individual runs, median, sample stddev и min–max без
заявлений о статистическом превосходстве.

Ключ сравнения нового брокера должен включать: сценарий и его версию; нативные
гарантии publish/consumer ack, persistence, fsync, replication и sessions;
логические producers/consumers и активные counts; topology/delivery; payload;
requested rate; warmup/measurement/cooldown; seed, ramp, timeout, очередь,
сбор метрик, настройки fault; clean/reuse; оборудование/OS/kernel/governor,
порты/сеть/swap; source commit, image digest, client-library version и настройки.
Полный YAML и метаданные находятся в `audit.json` и архивных манифестах.
`group_id` дополнительно учитывает все controls по ADR-0004. Он намеренно различен
между брокерами: для межброкерного сравнения нужна явная таблица соответствия
семантики, а не join только по `profile` или числу клиентов.

Новый брокер должен сначала воспроизвести density workload: один активный producer,
один consumer, остальные клиенты держат транспорт; 100 сообщ./с, полный envelope
256 байт, 60/300/30 с, пять повторов каждой доступной точки, тот же seed и controls.
Базовые точки — 100, 1000, 5000, 10000, 25000 логических клиентов. Проверять
реальные endpoints отдельно. Отсутствующие/неудачные точки baseline не заменять
нулями. Даже одинаковая машина после изменения kernel/настроек — новая среда;
для сильного сравнения лучше одновременно повторить эталонные брокеры на ней.

Для добавления данных реализуйте драйвер с явными возможностями, сохраните clean
commit и зафиксированные версии, используйте те же сценарии и raw contract.
Сохраните новые immutable runs отдельно. Прогоните штатный анализатор
`PYTHONPATH=analysis/src .venv/bin/python -m broker_analysis --results NEW_RESULTS --output NEW_ANALYSIS`.
Затем объединяйте per-run таблицы через документированный ключ workload и таблицу
гарантий, не усредняя процентили как общий поток. Скрипт публикации этой baseline
намеренно ограничен имеющейся финальной серией; расширять графики следует с
отдельными панелями для новых workload/сред/гарантий и проверкой счётчиков.
